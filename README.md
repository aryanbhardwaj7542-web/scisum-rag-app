# 🔬 SciSum RAG: Scientific Paper Assistant

A **Retrieval-Augmented Generation (RAG)** web app that lets you upload a research paper (PDF) and ask questions about it in plain English. Answers are generated by Google Gemini and grounded strictly in the text of your paper, which reduces hallucination.

## 🔍 Overview

Reading dense scientific papers to find a method, a metric, or a result is slow. SciSum RAG turns a PDF into a searchable knowledge base: it splits the paper into chunks, embeds them into a vector index, retrieves the passages most relevant to your question, and asks Gemini to answer using **only** those passages.

If the answer is not in the paper, the assistant is instructed to say so rather than invent one.

---

## ✨ Features

- 📄 **PDF upload and parsing** with `PyPDFLoader`
- ✂️ **Overlapping text chunking** so context isn't lost at chunk boundaries
- 🧠 **Semantic search** using Google Generative AI embeddings and a FAISS vector index
- 💬 **Question answering** through Gemini with a low temperature (0.2) for consistent answers
- 🛡️ **Grounded answers**: the system prompt forbids extrapolation and external data
- 🔑 **Bring-your-own API key**, entered in a password field and never written to disk
- 🧹 **Temporary file cleanup**: the uploaded PDF is deleted from disk after processing

## 🛠 Tech Stack

| Layer | Technology |
|---|---|
| Web UI | [Streamlit](https://streamlit.io/) |
| PDF parsing | [pypdf](https://pypdf.readthedocs.io/) via LangChain `PyPDFLoader` |
| Chunking | LangChain `RecursiveCharacterTextSplitter` |
| Embeddings | Google Generative AI (`models/embedding-001`) |
| Vector store | [FAISS](https://github.com/facebookresearch/faiss) (`faiss-cpu`) |
| LLM | Google Gemini (`gemini-1.5-flash`) via `langchain-google-genai` |
| Orchestration | LangChain Expression Language (LCEL) |

## 🏗 Architecture

```
 PDF upload
     │
     ▼
 PyPDFLoader ──► RecursiveCharacterTextSplitter (1000 chars, 200 overlap)
                              │
                              ▼
              Google embeddings ──► FAISS vector index
                                          │
 User question ──────────────► Retriever (top k = 4 chunks)
                                          │
                                          ▼
                     Prompt (system rules + retrieved context + question)
                                          │
                                          ▼
                              Gemini 1.5 Flash (temp 0.2)
                                          │
                                          ▼
                                   Answer in the UI
```

The chain is built with LCEL:

```python
rag_chain = (
    {"context": retriever | format_docs, "input": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)
```

### Key parameters

| Parameter | Value |
|---|---|
| Chunk size | 1000 characters |
| Chunk overlap | 200 characters |
| Retrieved chunks (`k`) | 4 |
| LLM temperature | 0.2 |

## 🚀 Getting Started

### Prerequisites

- Python 3.9 or newer
- A free **Google Gemini API key** from [Google AI Studio](https://aistudio.google.com/)

### 1. Clone the repository

```bash
git clone https://github.com/aryanbhardwaj7542-web/scisum-rag-app.git
cd scisum-rag-app
```

### 2. Create a virtual environment (recommended)

```bash
python -m venv venv

# macOS / Linux
source venv/bin/activate

# Windows
venv\Scripts\activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Run the app

```bash
streamlit run app.py
```

The app opens at `http://localhost:8501`.

## 💻 Usage

1. Paste your **Gemini API key** into the sidebar.
2. Upload a research paper in **PDF** format.
3. Wait for the "Document vectorized successfully" message.
4. Type a question, for example:
   - *"What methodology does the paper use?"*
   - *"What accuracy did the proposed model achieve?"*
   - *"What datasets were used for evaluation?"*
5. Read the answer generated from the paper's content.

If the paper doesn't contain the answer, the assistant replies that the detail is not contained within the provided paper.

## ⚙️ Configuration

Settings are defined directly in `app.py`:

| Setting | Where | Default |
|---|---|---|
| Chunk size / overlap | `RecursiveCharacterTextSplitter(...)` | 1000 / 200 |
| Number of retrieved chunks | `search_kwargs={"k": 4}` | 4 |
| Embedding model | `GoogleGenerativeAIEmbeddings(model=...)` | `models/embedding-001` |
| Chat model | `ChatGoogleGenerativeAI(model=...)` | `gemini-1.5-flash` |
| Temperature | `ChatGoogleGenerativeAI(temperature=...)` | 0.2 |

The API key is entered through the UI and kept in the process environment (`GOOGLE_API_KEY`) for the current session only. Do not commit keys to the repository.

## 🐞 Known Issues

These are limitations of the current code, listed so they are easy to fix:

1. **File uploader type filter.** `st.file_uploader(..., type="file")` should be `type="pdf"` (or `type=["pdf"]`), otherwise the browser's file filter will not match PDF files.
2. **Model names may be outdated.** Google retires older Gemini and embedding models over time. If you see a "model not found" error, update `gemini-1.5-flash` and `models/embedding-001` to currently supported model names from the Gemini API docs.
3. **Index is rebuilt on every interaction.** Streamlit reruns the script on each input, so the PDF is re-embedded every time you ask a question. Caching the vector store in `st.session_state` would save time and API calls.
4. **Error handling gap.** If document processing fails, the later code still references `retriever`, which would then be undefined. Stopping the script after the error (`st.stop()`) avoids this.
5. **No conversation memory.** Each question is answered independently, with no chat history and no display of the source passages.
6. **`requirements.txt` encoding.** The file is saved as UTF-16. Re-saving it as UTF-8 avoids install problems on some systems.
7. **Unpinned dependencies.** Package versions are not pinned, so a future LangChain release could break the app.
